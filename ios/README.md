# AlgolearnSpeak (iPhone app)

The iPhone as the speak server's microphone and speaker over WiFi. Protocol and
design: `../docs/DESIGN_PHONE_AUDIO.md` (sections 3 and 5).

The project is generated by XcodeGen from `AlgolearnSpeak/project.yml`; both the
yml and the generated `AlgolearnSpeak.xcodeproj` are committed. To regenerate
after editing the yml: `brew install xcodegen && cd ios/AlgolearnSpeak && xcodegen generate`.

## Run on your iPhone

1. `open ios/AlgolearnSpeak/AlgolearnSpeak.xcodeproj` (Xcode 26).
2. Select the AlgolearnSpeak target, Signing & Capabilities tab. "Automatically
   manage signing" is on; pick your Apple ID under Team (Xcode > Settings >
   Accounts to add it). `DEVELOPMENT_TEAM` is intentionally empty in the project.
   If Xcode says the bundle id `ai.algolearn.speak` is taken, change it to a
   unique one (for example `ai.algolearn.speak.frank`).
3. Plug in the iPhone (or pair wirelessly), enable Developer Mode on it
   (Settings > Privacy & Security > Developer Mode), choose it as the run
   destination, and press Run.
4. First launch on the phone: Settings > General > VPN & Device Management >
   trust your developer profile. Allow the microphone and Local Network prompts.

Free Apple ID signing expires after 7 days: the app stops launching and must be
re-run from Xcode (data and settings survive). A paid developer account signs for a year.

## Point it at the Mac

Start the speak server on the Mac (it listens on TCP 8772). In the app, enter the
Mac's LAN address in Server (default `192.168.86.188`; the field is remembered)
and tap Connect. The phone and Mac must be on the same WiFi. The badge shows
Idle / Speaking / Listening / Processing as the server reports; the mic level
meter and a haptic tick appear when the server opens the mic. The mic is sent
only between `mic_start` and `mic_stop`. Audio keeps running with the screen
locked (Audio background mode).

The orange microphone indicator in iOS is on for as long as the app is connected,
because the audio engine stays running to keep the background session alive. Nothing
is sent to the Mac outside `mic_start` / `mic_stop`.

Reconnect policy after a drop:
- Foreground: reconnects indefinitely, backoff 1 s doubling to 15 s.
- Background (screen locked or another app): keeps the audio session alive and keeps
  reconnecting for up to 2 minutes after the drop, then stops and shows Offline
  (tap Connect to resume). If the app was not yet connected when it went to the
  background, it waits until it returns to the foreground.
- `busy` (the server may still hold a stale slot for a few seconds after a WiFi
  blip): retried every 10 s, up to 6 attempts (about 60 s), then given up.
- `bad-rates`: not retried.

For the simulator, use `localhost` as the host.

## Build and test from the command line

The simulator name `iPhone 17 Pro` exists twice on this Mac, so xcodebuild
rejects `name=iPhone 17 Pro` as ambiguous. Use an id:

    xcodebuild -project ios/AlgolearnSpeak/AlgolearnSpeak.xcodeproj -scheme AlgolearnSpeak \
      -destination 'platform=iOS Simulator,id=96CF3880-2DB4-4BB4-B637-5BB2F0842522' -configuration Debug build

Replace `build` with `test` to run the unit tests (PCM conversion, JSON control messages).
